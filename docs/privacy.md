# Приватность: что видят сервер, логи и сторонние сервисы

Для владельца и того, кто разворачивает MASL. Главное правило: точный адрес и точку встречи видят только хост и одобренные участники; всем остальным — только ближайшая станция метро или МЦК.

## Сервер и логи

- Приложение не пишет журнал запросов Fastify и никогда не логирует `request.url`: в URL ленты и карточки встречи есть координаты зрителя.
- Ошибки базы пишутся без текста, параметров и `detail`: только класс ошибки, код PostgreSQL, имя ограничения и шаблон маршрута.
- Ключ DaData, набранные адреса и координаты в лог не попадают.
- Ответы API помечены `Cache-Control: private, no-store`: прокси и браузер их не кэшируют.

## Журналы доступа перед приложением

Caddy из `deploy/` журнал доступа по умолчанию не ведёт. Платформы (Render, Railway) и Caddy с включённым `log` записывают метод и полный URL каждого запроса. Поэтому:

- набранный адрес и точная точка хоста уходят только в теле `POST /api/places/suggest` и `POST /api/places/reverse`, не в URL;
- точное место новой встречи уходит в теле `POST /api/lobbies`;
- в URL ленты и карточки (`?lat=…&lng=…`) есть координаты зрителя, округлённые до 3 знаков (около 100 м). Если журнал доступа включён, он хранит примерное место зрителя. Не включайте журнал без нужды, а включив — ограничьте срок хранения.

## Сторонние сервисы

| Сервис                     | Что видит                                                                                                                                 | Когда                                                                                                                                                                                         |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenFreeMap (тайлы карты)  | Какие участки карты загружены и IP-адрес зрителя                                                                                          | Карта города; на вкладке «Карта» — тайлы вокруг самого зрителя, если она открылась по его геолокации или он нажал «Где я» (часто это район дома); в мастере — тайлы вокруг точной точки хоста |
| DaData (подсказки адресов) | Набранный хостом адрес и точку обратного геокодинга, округлённую до ~10 м. Без данных пользователя: запрос идёт с сервера, от имени ключа | Только при заданном `DADATA_API_KEY` и только в мастере создания                                                                                                                              |
| Яндекс Карты               | Точную точку встречи                                                                                                                      | Только когда хост или одобренный участник нажал «Открыть в Яндекс Картах»                                                                                                                     |
| CDN Telegram               | Запросы аватаров, без Referer (`referrerpolicy="no-referrer"`)                                                                            | Везде, где показан аватар                                                                                                                                                                     |

Кэш подсказок DaData на сервере свой у каждого пользователя: один пользователь не может узнать, что искал другой.

## Браузер

В хранилище браузера остаются только станция-точка отсчёта, недавние станции и черновик встречи без точки и адреса. Точное место и геолокация живут только в памяти вкладки.

## Принятые риски

- Участник, который ушёл со встречи, уже видел адрес.
- Станция выдаёт район встречи.
- Хост может сам написать адрес в названии или описании (мастер предупреждает).
- Без WebGL2 точка встречи может совпасть с точкой станции.
