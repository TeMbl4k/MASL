# Деплой на Railway

Что получится: проект Railway из двух сервисов, **PostGIS** (база) и **masl** (API вместе с Mini App), и адрес `https://<имя>.up.railway.app`, который открывается кнопкой в вашем боте. Интерфейс Railway на английском, ниже названия кнопок как в нём.

## 0. Перед началом

**Бот.** Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя и username (должен заканчиваться на `bot`). В ответ придёт токен вида `123456789:AA...`. Это пароль от бота: не пересылайте его никому. Если токен утёк, перевыпустите его в `/mybots` → ваш бот → API Token.

**Аккаунт Railway.** Зайдите на [railway.com](https://railway.com) через **Login with GitHub**. Пробный период даёт $5 на 30 дней без карты. Будет ли он полным, Railway решает по вашему аккаунту GitHub: в ограниченном пробном периоде сервисы урезаны и могут не запуститься из репозитория. Когда кредиты закончатся, сервисы остановятся, а через 30 дней без оплаты Railway удалит том с базой. Чтобы продолжить, нужен тариф Hobby ($5 в месяц). Оплата только картой через Stripe, и, по ответу поддержки Railway, карты российских банков не принимаются, так что понадобится иностранная карта.

**Две случайные строки** по 32+ символа: пароль базы и `JWT_SECRET`. Подойдёт генератор паролей (только буквы и цифры) или команда `openssl rand -hex 32`.

## 1. Проект

**New Project** → **Empty Project**.

Не выбирайте сразу GitHub Repo: Railway создаст отдельный сервис на каждый пакет монорепозитория, и лишние придётся удалять.

## 2. База PostGIS

1. **+ New** (или Ctrl/Cmd+K) → **Docker Image** → `postgis/postgis:16-3.5-alpine` → Enter.
2. Переименуйте сервис в `PostGIS` (Settings → Service Name). Имя важно: на него ссылается приложение.
3. **Variables** → **RAW Editor**, вставьте и подставьте свой пароль:

   ```
   POSTGRES_USER=postgres
   POSTGRES_PASSWORD=<случайная строка 1>
   POSTGRES_DB=railway
   PGDATA=/var/lib/postgresql/data/pgdata
   DATABASE_URL=postgresql://${{POSTGRES_USER}}:${{POSTGRES_PASSWORD}}@${{RAILWAY_PRIVATE_DOMAIN}}:5432/${{POSTGRES_DB}}
   ```

4. Правый клик по сервису → **Attach Volume** → путь `/var/lib/postgresql/data`. Без тома данные пропадут при перезапуске.
5. Публичный доступ (Public Networking, TCP Proxy) **не включайте**: приложение ходит в базу по внутренней сети.
6. Нажмите **Deploy**.

## 3. Приложение

1. **+ New** → **GitHub Repo** → `TeMbl4k/masl`. Если Railway попросит доступ к GitHub, разрешите его для этого репозитория. Railway сразу начнёт деплой из ветки `main`, где кода пока нет, и он упадёт: это нормально, ветку меняем на следующем шаге.
2. Переименуйте сервис в `masl` (Settings → Service Name), чтобы не путаться.
3. **Settings** → **Source**:
   - Branch: `stage-1-scaffold`, пока PR с этапом 1 не слит; потом `main`.
   - Root Directory оставьте пустым. Railway сам найдёт `Dockerfile` в корне.
4. **Variables** → **RAW Editor**:

   ```
   NODE_ENV=production
   PORT=3000
   DATABASE_URL=${{PostGIS.DATABASE_URL}}
   BOT_TOKEN=<токен от BotFather>
   JWT_SECRET=<случайная строка 2>
   ```

5. **Settings** → **Deploy** → **Healthcheck Path**: `/api/health`.
6. **Settings** → **Networking** → **Generate Domain**, порт `3000`. Получится адрес `https://<имя>.up.railway.app`.
7. Нажмите **Deploy**: изменения переменных применяются только после него.

Проверка: откройте `https://<имя>.up.railway.app/api/health`, должно быть `{"status":"ok"}`. Сам адрес в обычном браузере покажет «Откройте приложение в Telegram»: так и должно быть, вход работает только из Telegram.

Миграции базы применяются сами при каждом запуске. При первом деплое в логах может несколько раз появиться «База пока недоступна»: приложение ждёт, пока PostGIS запустится.

## 4. Подключить к боту

1. @BotFather → `/mybots` → ваш бот → **Bot Settings** → **Menu Button**.
2. Отправьте адрес `https://<имя>.up.railway.app`, затем название кнопки, например «Открыть».
3. Откройте чат с ботом и нажмите кнопку слева от поля ввода.

По желанию: **Bot Settings** → **Configure Mini App** → **Enable Mini App** с тем же адресом. Тогда в профиле бота появится кнопка запуска и ссылка `https://t.me/<username бота>?startapp`, которой можно делиться с фокус-группой.

## 5. Обновления

Каждый push в выбранную ветку Railway деплоит сам. После слияния PR переключите ветку в Settings → Source на `main`.

## Если что-то не так

- **Деплой упал.** Откройте сервис masl → Deployments и посмотрите, на каком этапе. Если на сборке, смотрите Build Logs: чаще всего выбрана ветка без кода. Если после запуска, смотрите Deploy Logs: сообщение «Некорректные переменные окружения» перечисляет, какую переменную поправить.
- **«DATABASE_URL не задан» или «База пока недоступна» до последней попытки.** Сервис базы должен называться ровно `PostGIS`, иначе ссылка `${{PostGIS.DATABASE_URL}}` пустая. Проверьте также, что сервис PostGIS запущен.
- **«Application failed to respond» по адресу приложения.** Порт домена не совпадает с портом приложения: в Settings → Networking у домена должен быть порт `3000`, а в переменных `PORT=3000`.
- **«Не удалось подтвердить вход через Telegram».** `BOT_TOKEN` в Railway от другого бота, не от того, из которого открыто приложение.
- **Не открывается из России.** Telegram с весны 2026 года без VPN почти недоступен. Есть сообщения, что часть адресов Railway тоже не открывается у некоторых провайдеров. Проверяйте с VPN.
- **Отладка в Telegram Desktop:** Settings → Advanced → Experimental settings → Enable webview inspecting, затем правый клик в Mini App → Inspect.
